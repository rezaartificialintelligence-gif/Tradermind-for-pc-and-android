من می‌خواهم از این مرحله به بعد پروژه TraderMind یک فرآیند کامل و خودکار برای GitHub و Build داشته باشد.

اولویت فعلی همچنان تکمیل آخرین Task پروژه یعنی حرفه‌ای‌تر، مدرن‌تر و زیباتر کردن ظاهر و UI برنامه است. این Task را کامل کن و بعد از اتمام تغییرات UI، فرآیند GitHub و Build خودکار را نیز آماده و فعال کن.

بخش 1 — اتصال Replit به GitHub

من Repository URL و GitHub Token را در اختیار تو قرار می‌دهم.

بعد از دریافت آن‌ها:

1. Repository فعلی پروژه را بررسی کن.
2. اتصال Git را به‌صورت صحیح تنظیم کن.
3. مطمئن شو Branch اصلی پروژه مشخص است.
4. تغییرات پروژه را با Commitهای منظم و قابل فهم به GitHub Push کن.
5. فایل‌های حساس مثل Token، Password، Secret و Credential را هرگز داخل سورس یا Commit قرار نده.
6. اگر لازم است از Environment Variable یا Secret استفاده شود، از روش امن استفاده کن.
7. قبل از Push، وضعیت Git را بررسی کن تا فایل‌های غیرضروری، build outputهای موقت یا Secretها وارد Repository نشوند.

بخش 2 — تکمیل زیباسازی TraderMind

قبل از Build نهایی، آخرین Task مربوط به حرفه‌ای‌تر کردن ظاهر TraderMind را کامل کن.

تمام تغییرات UI که قبلاً برای پروژه مشخص شده‌اند را اجرا کن.

مهم:

- فقط ظاهر را تغییر نده و عملکرد فعلی برنامه را خراب نکن.
- Responsive بودن صفحات را حفظ کن.
- مشکل نمایش Dashboard در حالت عمودی موبایل را نیز در صورت مرتبط بودن بررسی کن.
- ظاهر تمام Moduleها باید از نظر Design Language یکپارچه باشد.
- بعد از تغییرات، پروژه را Build و بررسی کن.
- خطاهای TypeScript، React، import، CSS و runtime را خودت اصلاح کن.

بخش 3 — GitHub Actions برای Build خودکار

می‌خواهم بعد از هر Push معتبر به Branch اصلی، GitHub Actions به‌صورت خودکار اجرا شود و نیازی به اجرای دستی Workflow توسط من نباشد.

یک CI/CD Pipeline مناسب برای TraderMind ایجاد یا اصلاح کن.

Pipeline باید حداقل این مراحل را داشته باشد:

1. Checkout کردن آخرین Commit
2. نصب Dependencyها
3. اجرای بررسی‌های لازم
4. Build پروژه
5. ساخت نسخه Windows با پسوند:
   .exe
6. ساخت نسخه Android با پسوند:
   .apk
7. بررسی موفق بودن Buildها
8. ذخیره فایل‌های نهایی به‌عنوان GitHub Actions Artifacts
9. در صورت موفقیت Build، وضعیت را به‌صورت واضح در GitHub مشخص کن.
10. در صورت Failure، Log کافی تولید کن تا علت خطا مشخص باشد.

بخش 4 — Build باید کاملاً خودکار باشد

هدف نهایی این است:

Replit
↓
Commit
↓
Push به GitHub
↓
GitHub Actions به‌صورت خودکار اجرا شود
↓
Build Windows
↓
ساخت Setup.exe
↓
Build Android
↓
ساخت APK
↓
آپلود Artifactها
↓
اعلام موفقیت یا خطا

من نباید برای هر نسخه به‌صورت دستی وارد GitHub شوم و Workflow را Run کنم.

بخش 5 — مدیریت خطا

اگر Build شکست خورد:

- علت Failure را بررسی کن.
- در صورت امکان خودت کد یا Workflow را اصلاح کن.
- دوباره Build را اجرا کن.
- تا زمانی که مشکل قابل حل است، کار را نیمه‌کاره رها نکن.

اما مراقب باش Loop بی‌نهایت ایجاد نشود.

اگر مشکل مربوط به Secret، Permission، Token، Signing Key یا تنظیمات GitHub بود که از داخل پروژه قابل اصلاح نیست، دقیقاً اعلام کن چه موردی نیاز به تنظیم دستی دارد.

بخش 6 — خروجی نهایی

در پایان باید بتوانم در GitHub یک فرآیند مشخص داشته باشم که:

- Source Code در Repository باشد.
- هر Push معتبر باعث اجرای خودکار Build شود.
- Windows Setup.exe ساخته شود.
- Android APK ساخته شود.
- فایل‌های Build به‌عنوان Artifact ذخیره شوند.
- وضعیت Build مشخص باشد.
- اگر Build شکست خورد، دلیل آن در GitHub قابل مشاهده باشد.
- برای اجرای Workflow نیازی به اقدام دستی من نباشد.

قبل از ایجاد هر Workflow جدید، Workflowهای فعلی Repository را بررسی کن تا Workflow تکراری یا متناقض ایجاد نشود.

همچنین اگر Workflow فعلی وجود دارد، ابتدا آن را تحلیل کن و در صورت امکان همان Workflow را اصلاح و کامل کن.

در پایان، کل زنجیره را با یک Push آزمایشی بررسی کن و مطمئن شو که فرآیند از Commit تا Build و تولید APK و Setup.exe واقعاً کار می‌کند.

در پایان گزارش بده:

1. چه فایل‌هایی تغییر کردند.
2. چه Workflowهایی ایجاد یا اصلاح شدند.
3. چه Buildهایی انجام شد.
4. نام Artifactهای تولیدشده چیست.
5. آیا APK با موفقیت ساخته شد؟
6. آیا Setup.exe با موفقیت ساخته شد؟
7. آیا Workflow بعد از Push به‌صورت خودکار اجرا شد؟
8. آیا هیچ مرحله‌ای نیاز به اجرای دستی دارد یا خیر.
